# Fresh Decisions comparison fixture

This is a new public-synthetic evaluation set authored before any comparison inference. It contains 32 streaming-window cases and 16 finalized user/revision cases, with eight and four cases respectively for each Agent route. References are synthetic author judgments, not human ground truth. Lead review must precede any call. No previous Laya development/reserved case files or model answers were read or reused to author these cases.

## Frozen input boundary

`fixture-inputs.json` stores the exact bounded native classifier state (`native_state`), the current Laya adapter projection (`adapter_state`), and the exact shared `model_input` containing `_render_state` text plus `_window_questions`/`_finalized_questions`. Window inputs were independently compared with the actual `WindowClassifier._request_body`; all inputs pass the current adapter parser. Source hashes and baseline are in `manifest.json`. The Agent history repair on inspected HEAD does not modify these Decisions sources.

Give every model only the same case's `model_input.state` and `model_input.questions`; do not send case IDs, this document, native metadata, reference labels, tags, rationales, or sequence annotations. Protocol envelopes may differ only as required by each provider's supported structured-choice transport, with the exact state, question wording, criteria, and option ordering preserved. Do not silently add task objectives, semantic task names, examples, scratchpad, conversation history from another case, or supplementary policy instructions. Task entries expose only task_id, objective_revision, and state. All task IDs are fictional. No real transcript, task, audio, or credential is present.

Finalized sources are `conversation.user` or `conversation.revision`. Assistant-output negatives are earlier `conversation.converse` context; an assistant latest source normally bypasses classification in the native worker, so it is not charged as an artificial model case. Window utterance/window/revision identifiers are native projection fields removed by the current adapter before rendering. Sequence groups contain fixed cumulative speech hypotheses and supplied earlier context; each case is evaluated independently, without model-output chaining or waiting for another case's answer.

## Reference interpretation

The shared typed questions are the scoring contract. The Agent route describes work intent independently of whether a unique target is available. An explicit correction/cancellation of an unlisted task, or a request to affect multiple tasks, can therefore have correction/cancellation intent and target NONE. This is not a claim that the native worker would execute it: native source, currentness, ambiguity, target, revision, approval, and disclosure gates remain separate. **Audit finding:** the generic finalized classifier prompt also says ambiguous targets should ignore, while these typed questions separate work intent from a NONE target. Preserve this mismatch in the comparison report; do not count agreement with the typed intent reference as an accuracy win for native executor routing. Report unbound correction/cancellation cases separately. This fixture evaluates the current Laya typed-question projection, not equivalence of all native dispatch paths, and does not measure native admission/dispatch eligibility.

Every actionable reference has one exact target choice if tasks exist, including NONE for absent/ambiguous/multiple targets. When there are no tasks, the native question set omits target and normalized target/revision are null. For ignore/conversation, the current adapter clears target/revision regardless of the target head: all offered target labels are explicitly acceptable and excluded from target accuracy. All references have one exact Agent route and, for windows, one exact conversation timing label; no ambiguous route set is used. Acoustic flags are hints only; complete requests can use user_speaking=true and partial/backchannel examples can have capture_ended=true.

`fixture-references.json` is withheld from models. It records expected raw choice labels, normalized native labels/target/revision, coverage tags, and concise author rationale. It contains no outcomes, confidence claims, or model ranking. Case IDs are identifiers only; the manifest order is binding even though IDs describe authoring order.

## Fixed execution and scoring rules

Run each declared model once per case in the frozen order. Do not retry, repair output, substitute a fallback, reorder after errors, tune prompts/thresholds from answers, or change references. Exactly one initial attempt per model/case; a timeout, refusal, malformed/extra/missing output, invalid label, response truncation, unavailable model, transport error or admission denial is a failed case, not an ignore result and not a skipped denominator. Never invent confidence for a provider that does not supply it. Preserve raw answer, parsed labels, actual model/provider identity, status/error category, latency boundary and usage/billing-knownness separately in the parent runner. This fixture authorizes no requests; the parent declaration must pin model list, transport/envelopes, timeout/output caps, local resource ownership and the aggregate $10 comparison admission cap before inference. Stop further admissions on budget uncertainty; do not call unattempted cases successful. Report any incomplete budget-limited run with attempted and unattempted counts.

Report separate window/finalized and pooled raw typed Agent-intent exact accuracy and per-class confusion, window-only conversation timing exact accuracy and confusion, actionable target accuracy (choice plus exact native ID/revision, including NONE), and joint case accuracy. Joint means all applicable timing, route and scored target fields correct; ignore cases require normalized null target/revision. Errors count as incorrect in every applicable accuracy denominator. Also report false-work rate on reference ignore cases (valid non-ignore prediction / 12) and false-interrupt rate on reference non-interrupt cases (valid interrupt prediction / 36), with error counts beside these rates so a failing model cannot appear safe merely by refusing. Do not count an unparseable error as an observed interrupt; report pessimistic bounds `(observed harm + errors in that negative subset) / subset size` alongside the observed rates. Missing exact target/revision is failure even if route alone matches. No dispatch, permission or task-success rate can be inferred from this classification-only fixture.

This small, manually authored, non-blinded-after-release set is not a population estimate or held-out product acceptance result. It tests textual projection and labels, not actual STT/audio latency, prosody, real overlapping speech, multi-session isolation, native execution acknowledgments, or model reliability across retries. Once consumed it is no longer fresh; retain all outcomes and failures without relabeling it as a new reserved set.
