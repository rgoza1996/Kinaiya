# ADR 0025: Local character activation and presentation settings

Status: experimental implementation for [#63](https://github.com/rgoza1996/Kinaiya/issues/63) under [#8](https://github.com/rgoza1996/Kinaiya/issues/8), Roadmap §§15.3–16.4 and M5. Extends [the sprite renderer](0015-mascot-sprites.md) and [retained views](0024-concept-layout.md). Full expressions, provider setup, native/device voice and broader M5 acceptance remain open.

The former client validated pack palettes without consuming them and loaded only the bundled pack. An independent presentation controller now owns a validated character selection and local display preferences. It has no service client, runtime AppState, provider, permission or personality access. KinaiyaApp owns or accepts that controller independently of runtime state. Palette changes rebuild themes without changing the HomeShell key or either retained pane. Pack/bundle values come from the same selection during FutureBuilder transitions.

The [package format](../character-packs.md) is a bounded self-contained JSON envelope around the existing v2 manifest. It adds strict structure/duplicate-key checks, exact referenced-file membership, canonical base64, source checksum/provenance text, pre-decode PNG structure/CRC and aggregate allocation checks, then actual static-image engine decoding. Validated selections have a private constructor, frozen metadata and copy-on-read memory assets; imported paths cannot fall through to a filesystem, URL or another pack. The renderer still verifies and owns its decoded texture and falls back safely.

Appearance provides inspection/real preview before explicit activation, export and original restoration. Owner colors override pack palette, then defaults. Cached light/dark themes derive contrasting controls for custom colors while preserving the existing exact default schemes. The moon/reflection consumes the selected colors; non-character presentation removes that scene and retains transcript/controls. User reduced motion composes with the platform setting and never forces animation against it. Application identity/logo, personality and inference choices remain separate from artwork.

One IndexedDB record atomically persists only preferences and an optional canonical imported package. Restoration is revalidated; controller revision checks protect newer actions from delayed reads/default loads. Writes are serialized and stale queued snapshots are skipped. Persistence failures leave current presentation active and are displayed alongside action messages. The web bridge bounds file size before reading, supports cancel, limits storage transactions, and revokes temporary download URLs. Native platform helpers explicitly report session-only state and unsupported import/export. No backend migration or automatic remote fetch is added.

## Verification and limits

Deterministic checks use public synthetic images and transport/audio fixtures. Package tests exercise strict types/fields, escaped duplicate keys, nesting, missing/extra/duplicate files, traversal/URLs, checksums, PNG/APNG/corruption and byte/pixel limits. Controller tests cover immutable asset ownership, default/export round trips, invalid restoration, delayed loads versus newer choices, ordered writes, failures and disposal. Settings tests inspect a real decoded preview, explicit activation/cancel, narrow/2× text controls, native notices, persistence warnings, timeouts and stale callbacks. Integration tests observe actual sprite/image geometry and palette changes while retaining pane instances, both drafts/sessions, tasks/approvals and the armed adapter; no command, transcription, task interrupt or new session is invoked.

Browser verification imported a tiny public synthetic animated pack, observed new artwork/palette, reloaded its persisted state, exported a real file with identical manifest/image bytes, and restored explicit colors/motion/non-character preferences. The preview uses a separate origin from the live reference. Browser bridge Node tests use mocked isolated DOM/IndexedDB seams; they supplement actual browser behavior rather than representing physical-device testing. The existing audio_bridge.test.js CI entrypoint also loads presentation_bridge.cases.js, so both suites run without broadening workflow-edit credentials.

A bounded actual Muse Contributor/xhigh static review of the pack/controller/storage/bridge source reported no actionable findings; it ran no tests. Independent Codex integration review identified pack/bundle transition atomicity and hidden persistence-warning defects, both repaired with regressions. Neither is human approval or proof of production security. The remaining full expression library, weighted variants/cooldowns, warmup choreography, physical audio/performance, native persistence and complete provider/setup workflows remain open. ZIP packaging, cross-device/cross-tab preference synchronization and personality/voice import are not implemented by this slice.
