# ADR 0112: Buffered native audio turns

Issue: #451, under #204 and #357. This increment admits original audio to an owner-managed external realtime endpoint. It does not implement duplex capture, video ingestion (#449), or model-specific inference.

## Admission and transport

An explicit host `native_audio` declaration pairs `kind: realtime_v1`, `base_url`, `model`, and optional `api_key_env` with the existing local host Converse selection. Optional `max_output_tokens` (16–4096, default512) and `timeout` (at most90 seconds) bound generation. The endpoint is literal loopback HTTP, optionally ending in `/v1`; the adapter uses its `/v1/realtime` WebSocket interface. Install the pinned `native-audio` extra explicitly when this transport is needed. Ordinary text/voice configurations remain unchanged when the declaration is absent; malformed or unavailable declared audio never falls back to text or TTS.

This first host-only mode refuses resource-managed or independently selected catalog models. The operator manages the external engine and qualifies its protocol. A matching alias does not prove immutable model weights or server incarnation. No native audio token-count interface is available here: qualified journal history is paged to exhaustion under existing time/byte bounds and sent as labelled historical data, while the current original PCM is sent as audio. Kinaiya neither fabricates an exact token count nor clips old turns to a fixed reply count. Endpoint overflow refuses the operation. Selected memory recall is explicitly unavailable in this mode.

A transcription-intent connection may initially announce a valid realtime session before applying the explicit transcription update. Both initial transcription and initial realtime PCM envelopes are validated. In either case, the matching transcription acknowledgement is mandatory before any input audio is sent; the URL intent alone grants no release.

The authenticated `POST /v1/converse/native-audio/clips` accepts strict session/thread/epoch, utterance/request UUIDs, disclosure scope and base64 WAV. Only canonical 44-byte-header PCM16 mono16000 Hz WAV, nonempty and at most30 seconds, is accepted. A bounded raw-body gate precedes JSON validation and never reflects invalid audio. Original decoded PCM is transcribed through the same captured endpoint with transcription intent. The authoritative authenticated-user `conversation.window` retains its audio digest, scope and native identities for Decisions and the normal transcript. Native conversational generation receives that same original PCM, not a text replacement of its transcription.

## Ownership and replay

A protected SQLite intent ledger durably reserves request and utterance identity before ASR. Exact in-process duplicates join the same original task. Changed requests, lost clips after restart, stale epochs and unavailable originals refuse without a second ASR. The ledger retains at most4096 intents without eviction; RAM retains at most32 clips and16MiB, reserving room for input copies and up to2MiB output before admission. Saturation refuses rather than evicting a live receipt.

The provider retains original acquisition, send/receive, response and close futures across cancelled observers. Repeated cancellation cannot restart the bounded cleanup wait or transfer custody to a replacement transport. Export requires confirmed close and a final authority/deadline check. Unconfirmed cleanup stays unavailable with its original work retained. Owner shutdown similarly retains the original provider and closer.

The shared `settled_converse_operations` model-change boundary uses exactly ten base operation names: `preparing`, `text`, `text_admitting`, `windows`, `speech`, `stt`, `stt_cleanup`, `native_audio`, `playback_pending`, and `memory_pending`. The `native_audio` count is a bounded integer0 or1: zero when no native owner has pending work, and one while its original work, uncertain admission, shutdown or failed cleanup remains retained. Standalone and HTTP-wired runtimes expose the same complete set. The independent [text](0091-converse-text-model-settings.md), [STT](0099-independent-stt-model-settings.md) and [TTS](0101-independent-tts-model-settings.md) owners, and their Flutter metadata parsers, retain exact-name and bounded-integer validation. Any nonzero count still blocks model changes; missing, unknown or malformed counts remain unavailable rather than being filtered away.

## Native output and browser consent

Strict matching session/response/item identities, terminal completion, exact text consistency, bounded PCM and declared sample rates are required. Only an unchanged guarded reply can retain native PCM: if the runtime replaces an unsupported work claim, the original speech is suppressed. The confirmed journal append caches the reply before it becomes visible to speech consumers.

The existing `/speech` endpoint validates that exact native event and emits its retained PCM through existing generation, stop and delivery ownership. It bypasses separate TTS configuration and never synthesizes a replacement for missing native speech. Flutter's explicit audio-import gesture owns only its matching turn. It defers fast-polled output until the exact upload receipt confirms the original source, and retires that permission on source, connection, session, epoch or turn changes. Playback completion is reported only by the real player completion callback. This import permission does not arm a microphone or authorize unrelated queued speech. The exact admitted current clip binds one atomic reply identity and may reconcile its authenticated service generation even when a failed import or service restart left the optimistic local interruption counter higher. Duplicate replies cannot reset that counter or playback; ordinary rolling-window epochs retain their monotonic gate. The web import gesture requests playback-context activation before opening the file picker, without waiting for resume, starting PCM, or acquiring a microphone. Later queueing requires the actual context to be running; only original source completion acknowledges playback.

## Browser Call and input ownership

For an explicitly configured, available native audio owner, **Call Kinaiya** uses the same original-PCM admission as audio import. The optional `NativePcmCaptureAudio` browser capability must be present; unavailable capture refuses visibly without a separate transcription, rolling-window, text or TTS fallback. Configurations without native audio retain their existing modular Call path. This remains buffered whole-utterance transport, not a claim of provider duplex support.

Native capture has a separate AudioContext whose actual rate must be 16000 Hz. Confirmed speech starts a whole utterance with at most 40000 pre-roll samples; at most 480000 samples (30 seconds including that pre-roll) can be finalized as canonical PCM16 mono WAV. Silence alone produces no clip. Overflow refuses the entire unfinished utterance, rather than admitting a shortened prefix. The existing VAD remains active during submission and reply playback, so spoken interruption immediately stops local PCM and retains the original service-interrupt barrier.

One original admission and at most one additional finalized pending clip are retained. Further speech with a full pending slot stops actual capture visibly without replacing that slot. A stopped microphone and a logically active, stoppable Call are separate states. Original admission identity and semantic outcome survive retirement of its playback permission: only an exact authenticated source receipt confirms admission. A failed or mismatched acknowledgement after a POST is unknown and blocks automatic submission of the pending clip, even after the interrupt barrier settles. Supersession before any POST is distinguishable from an unknown attempted POST. Stop, disconnect, source-generation, disclosure and session/thread/epoch changes fence unsubmitted work and obsolete output; none proves that an attempted remote admission had no effect.

`AudioInputSelection` provides explicit local enumeration, selection and **Use system default**. Discovery uses `enumerateDevices` only, with at most 128 inventory rows and 4096 characters per ID/label; it never opens a microphone to populate labels. An explicit selected ID is session-RAM state, used as an exact `getUserMedia` constraint and checked against the actual single audio track's device ID. A missing, changed or mismatched selected device fails visibly without default fallback. Selection is refused during acquisition, active capture or stop. Browser IDs/labels are not sent to the host or providers, journalled, exported or persisted; these controls do not change OS defaults. Browser permission and device-label availability remain platform constraints.

Otherwise valid browser inputs with empty identifiers are omitted from selection; exposed nonempty identifiers remain selectable after the complete inventory passes validation. If inputs are present but all their identifiers are empty, discovery stays unavailable and reports the fixed `identifiers-unavailable` reason. Malformed fields, duplicate nonempty identifiers and exceeded bounds still refuse the whole inventory. Discovery does not acquire permission. Dart recognizes only the exact unavailable response envelope; other malformed results and API failures remain generic. The notice states that the browser has not provided selectable identifiers, suggests checking site permission and refreshing, and confirms that this refresh activated no microphone. It does not diagnose permission denial or assert the state of a separate capture operation.

Voice options use the configured native mode even before Call starts or while capture is paused. They describe buffered whole utterances, end-of-speech detection and the 30-second limit, with the existing applicable silence/confirmation controls. This presentation does not change capture timing, admission or provider behavior; the modular streaming-window and fallback descriptions retain their separate modes.

The independent `native_call_input_selection.test.js` and `native_call_input_test.dart` fixtures cover canonical PCM and whole-utterance bounds, explicit device ownership, held operations, interruption, unknown acknowledgements, currentness fences and no legacy fallback. They provide controlled browser/widget evidence; actual private-input capture, external-engine speech and audible playback still require a separate rehearsal.

## Verification and limits

Independent scripted-transport and real Store/runtime/API tests cover original PCM, journal identity, complete history, no-count/no-TTS traps, replay, limits, stale authority, held cleanup and native delivery. Flutter tests cover canonical WAV, HTTP/receipt identity, fast polling, unarmed import playback and retirement. Existing schema hashes remain unchanged. Exact local test and CI outcomes belong in the PR; a scripted transport is not real inference or audible playback proof. The rehearsal must separately record actual external-engine speech input/output and browser playback.
