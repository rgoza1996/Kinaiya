## Scope and source mapping

The patch changes the **content area** of sixty existing boards (thirty per
motion mode), preserving their board IDs, header, sidebar, app rail and existing
shell navigation. They comprise Models, Harness Customization, all fifteen
linked harness editor/selection states, Providers and its eleven linked setup
states, and Memory. It adds fifty detail/state boards inside the same
master, with native navigation back to the relevant existing sections.
It does not create another draft or import a replacement file.

### Capability boundaries represented by the design

- Catalog choices apply to Agent default, exact-harness overrides and the five
  auxiliary text purposes. Converse, Decisions, STT and TTS remain host-managed.
- Saving a provider declaration does not apply it to an active role. Current
  model readiness and quality remain unverified.
- Measured native LM Studio supports `none` reasoning; Meta text requires its
  native admission and explicit context/credential configuration. Compatible
  and Laya declarations do not become eligible Agent text-completion choices
  merely by being saved.
- No OAuth success, automatic probe, inferred modality, direct audio,
  credential discovery, fallback route or implicit cloud disclosure is added.
- Notes remain owner-curated, local-only, immutable and source-bound. Forget
  removes dependent notes; it does not delete the authoritative transcript.
- A timeout leaves the outcome unknown. A receipt lookup is distinct from an
  exact replay; historical memory requests cannot be retried in another scope.

## Prepared local plugin

Files live only in the managed worktree's ignored directory:

```text
.dev-run/options-native-design-update/
  expected-baseline.json   Exact metadata from the matching tracked archive
  plugin.source.js        Readable patch implementation
  assemble.py             Offline self-contained plugin assembly
  plugin.js               Prepared Penpot plugin code
  manifest.json           content:read and content:write only
  index.html, ui.js        Inspect and explicitly Apply controls
  icon.svg
  serve.py                Explicitly started loopback static host
  README.md
```

The plugin borrows the API pattern from prior ignored
`.dev-run/harness-options-revision/` and `.dev-run/harness-options-labels/`
helpers. Those old builders must not be rerun: their original name lookups
precede later board renames. The new patch guards the audited identities.

It refuses a different file/page/name, changed expected board dimensions,
changed direct-child IDs/names, changed content geometry or missing navigation
destination. It rechecks each target immediately before replacing content.
Any existing `Options native /` detail board prevents another application.
This is intentionally a single-use patch; reconcile a changed baseline rather
than weakening the checks.

Before mutation it saves **Before native Options provider, memory and model
sync**. New details are built before existing content changes. Failure before
content replacement removes the newly created boards; later failure reports a
possibly partial update and requires restoring the named recovery version.
It preserves existing flow records and uses `220ms` dissolve/ease-in-out for
motion-on navigation. Motion-off and dropdown-only transitions remain instant.
New detail grids use a computed motion-mode offset based on their row count,
with additional separation, so their two modes cannot overlap. Planned content
and link rectangles must fit inside the replacement region before mutation.
The final named version is **Native Options · provider catalog, immutable notes
and exact Agent model choices**.

### Application and review, for the applying owner

1. Finish source review and the intended native-code verification first. Keep
   the current editable master open; do not import a new file.
2. If source is revised, run the offline assembler again. Explicitly start the
   prepared `serve.py` when ready; its static manifest URL is
   `http://127.0.0.1:8813/manifest.json`. The host serves only the five named
   plugin resources and has no credential, proxy or upload endpoints.
3. Load that manifest through the local Penpot plugin workflow. Choose
   **Inspect existing master**. Confirm the sixty-board baseline match. A
   mismatch requires a fresh export and reconciliation before any mutation.
4. Choose **Apply prepared patch**. Wait for the final saved-version message.
   If application fails, inspect the reported phase and restore the named
   recovery version after any content replacement. Do not rerun a partial patch.
5. Visually review editable desktop boards: top alignment, text fit, native
   selectors, credential forms, source/generation labels, note provenance and
   destructive copy. Follow each selected prototype route in both motion modes,
   including dedicated harness editors, inherited/custom auxiliary states and
   recovery. Verify old hidden content hotspots were removed from content areas.
6. Keep unverified/unsupported runtime behavior visibly distinct from design
   examples. Record the actual review result; this plan does not assert it.

No servers were started and no Penpot API was called during preparation.
The plugin does not export, publish, read credentials, call a model, capture
audio/video, change runtime settings or perform Git operations.
